# 设计制作流程与修缮指南

> 本文档回答三个问题：
> 1. **这个项目是怎么设计出来的**（思路、架构、为什么这么写）；
> 2. **每一行代码在干什么**（模块级解读，便于面试讲解）；
> 3. **你怎么修改和扩展它**（新增公式、新增拟合、改报告模板…）。

适用对象：希望真正理解并二次开发本项目的同学（本项目的评审标准之一就是“能独立运行、修改、解释自己的作品”）。

## 一、项目定位与设计思路

### 1.1 它解决什么问题

光电专业学生的日常痛点：实验做完后要
1. 查公式手算（容易错、单位易混）；
2. 用最小二乘法拟合数据（手算繁琐、Excel 操作啰嗦）；
3. 按教材流程评不确定度（步骤多、t 因子表要翻书）；
4. 手动拼实验报告（排版耗时）。

本项目把这四件事合并成一个本地网页工具：**粘贴数据 → 出结果 → 导报告**。

### 1.2 为什么选这个技术方案

| 候选方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 纯 Python 脚本 / CLI | 最简单 | 交互差，招新演示不直观 | 弃 |
| Excel + VBA | 同学熟悉 | 跨平台差、算法封装弱、难开源展示 | 弃 |
| **Python + Gradio** | 网页界面美观、演示效果好、代码量小、社区成熟 | 需装依赖 | ✅ 选用 |
| 网页 HTML/JS 纯前端 | 免安装 | 拟合算法与 Word 导出实现成本高 | 弃 |

Gradio 的核心价值：**用很少的代码做出像样的交互界面**，把精力留给算法本身，适合“小项目 + 演示视频”的招新场景。

### 1.3 为什么界面与算法分离

```
app.py（界面层）        core/（算法层）
  用户输入 ──────────►  formulas/fitting/uncertainty/report
  展示结果 ◄──────────  纯函数，不碰界面
```

- **算法层（core/）**：只做计算，输入输出都是普通 Python 对象，不依赖 Gradio；
  → 好处 1：可以在 Jupyter / 命令行单独使用；
  → 好处 2：换界面（比如改成网页版）不需要重写算法；
  → 好处 3：便于自动化测试（self_test.py 只测 core/，不启动界面）。
- **界面层（app.py）**：只负责收集输入、调用 core/、展示输出。

面试时可以直接说：**“我把计算和界面解耦，算法可以独立测试和复用，这是工程上很基本的模块化思想。”**

## 三、核心算法逐模块解读

### 3.1 `core/formulas.py` —— 公式“注册表”模式

**设计核心：公式即数据。** 每个公式是一段描述（名字、公式文本、物理量、求解函数），而不是一堆散落的 if 分支。界面层遍历注册表就能自动生成输入框，新增公式不用改界面。

```python
FORMULAS = [
    {
        "key": "thin_lens",
        "name": "薄透镜成像公式",
        "formula": "1/f = 1/u + 1/v",
        "symbols": [("f", "焦距 f", "cm"), ("u", "物距 u", "cm"), ("v", "像距 v", "cm")],
        "solve": solve_thin_lens,
    },
    ...
]
```

**求解函数约定**：参数即物理量，未知量传 `None`，返回 `(填充后的字典, 附加说明列表)`。

```python
def solve_thin_lens(f=None, u=None, v=None):
    if f is None:
        f = u * v / (u + v)
    elif u is None:
        u = f * v / (v - f)
    elif v is None:
        v = f * u / (u - f)
    return {"f": f, "u": u, "v": v}, []
```

**注意的工程细节（面试可讲）**：
- **单位换算内聚在公式内部**：如光栅方程中 d 用 μm、λ 用 nm，在函数内部统一换算，用户不用管；
- **物理合法性校验**：`_check_positive`（正数校验）、`_check_angle_sin`（sin > 1 时报“无实数解”）、整数级次校验；
- **报错信息中文且可操作**：比如“请恰好留空一个待求量”。

### 3.2 `core/fitting.py` —— 三种拟合 + 数值算法

**数据解析 `parse_xy`**：用正则切分每行，兼容逗号/空格/制表符/分号；遇到非数字行（表头）自动跳过；2 列或 3 列（含 dy 误差棒）。

**线性拟合 `linear_fit`**：最小二乘闭式解（教材公式），并给出斜率与截距的标准误差：

```
k = (n·Σxy − Σx·Σy) / (n·Σx² − (Σx)²)
b = (Σy − k·Σx) / n
dk = s / √(Σ(x−x̄)²)         其中 s² = Σ残差²/(n−2)
db = dk·√(Σx²/n)
```

**多项式拟合 `poly_fit`**：直接调用 `numpy.polyfit`（最高次到常数），R² = 1 − SS_res/SS_tot。

**自定义函数拟合 `custom_fit`** —— 本项目最值得讲的算法部分：
- 用正则从表达式 `a*exp(-b*x)+c` 中提取参数名 `a,b,c`（排除 `x` 和数学函数名）；
- 用 `eval` 编译表达式为可调用函数（**禁用了 `__builtins__`，只开放数学函数，避免任意代码执行**）；
- **Levenberg-Marquardt 算法（纯 numpy 实现）**：在高斯-牛顿法与最速下降法之间自适应切换，迭代规则为

```
(JᵀJ + λ·diag(JᵀJ))·δ = −Jᵀr        （J 为残差 Jacobian，r 为残差）
λ 减小 → 更像高斯-牛顿（快速收敛）
λ 增大 → 更像最速下降（保证稳定）
```

**开发中踩过的坑（面试可直接讲）**：
> 一开始把 LM 迭代步方向写反了（漏了负号），拟合结果永远停在初值、R² 为负。通过自检脚本里“指数衰减数据拟合回真值”的用例把它抓了出来——**这正是先写自检、再写界面的价值**。

**绘图 `plot_fit`**：matplotlib，设置 `font.sans-serif` 为中文字体、`axes.unicode_minus=False` 避免负号乱码；用 `Agg` 后端（不弹窗，直接出图）。

### 3.3 `core/uncertainty.py` —— 不确定度评定

**直接测量**（对应大学物理实验教材流程）：

```
平均值  x̄ = Σxᵢ/n
标准偏差 s = √(Σ(xᵢ−x̄)²/(n−1))                    （贝塞尔公式）
A 类    uA = t₉₅(n−1)·s/√n                        （t 因子表内置）
B 类    uB = Δ仪/√3                               （仪器允差按均匀分布）
合成    u = √(uA² + uB²)
扩展    U = k·u                                   （k 默认 2，约 95%）
结果    x = x̄ ± U
```

t 因子表直接内置在 `_T_TABLE` 字典中（ν=1 时 12.71 … ν→∞ 时 1.96）。

**误差传递**：对任意表达式 `y = f(x1,x2,…)`，用**数值中心差分**求偏导：

```
∂f/∂xᵢ ≈ [f(xᵢ+h) − f(xᵢ−h)] / 2h
uy = √( Σ(∂f/∂xᵢ · uxᵢ)² )
```

好处：不用针对每条公式手推偏导；坏处（面试可提）：数值差分有微小截断误差，但对实验数据精度足够。

### 3.4 `core/report.py` —— Word 报告生成

用 `python-docx` 从零拼文档，按实验报告标准结构输出七个部分：

```
标题 → 信息表(姓名/学号/班级/日期/指导教师)
一、实验目的  二、实验原理  三、实验仪器与装置
四、实验数据（表格）  五、数据处理（拟合结果+拟合图+不确定度）
六、结果与分析  七、结论
```

**中文字体关键点**：Word 里中文字体要同时设置 `w:eastAsia` 属性，否则中文显示为默认西文字体。工具函数 `_set_run_font` 统一处理（正文宋体、标题黑体、西文 Times New Roman）。

## 四、界面层解读（app.py）

每个标签页一个 `build_*_tab()` 函数，内部完成：**定义组件 → 绑定回调**。

以“公式计算器”为例：

```python
formula_dd.change(on_formula_change, inputs=[formula_dd], outputs=[guide_md] + inputs)
calc_btn.click(compute_formula, inputs=[formula_dd] + inputs, outputs=[result_md])
```

- `change`：切换公式 → 刷新说明文本、显示对应物理量输入框（`gr.update(visible=..., label=...)`）；
- `click`：收集输入 → 调 `compute_formula` → 展示结果。

**输入框复用技巧**：14 个公式的物理量个数不同（2~4 个），界面只预定义 4 个输入框，通过 `visible` 动态显隐——避免为每个公式单独写一组组件。

回调函数的输入输出全部是 `(组件, 组件, …)` 的对应关系，这是 Gradio 的基本模型：**输入组件 → Python 函数 → 输出组件**。

## 五、从零到一的开发流程（复刻路线）

如果你以后想做类似项目（或需要向面试官讲“我是怎么一步步做出来的”），建议按这个顺序：

```
第 1 步：定需求（明确场景与核心功能）       → 本文档 1.1 的四件事
第 2 步：写核心算法（不碰界面）             → core/ 四个模块
第 3 步：写自检脚本（先证明算法对）          → self_test.py
第 4 步：搭界面（把算法接上）               → app.py
第 5 步：冒烟测试（服务能起、页面能开）      → smoke_test.py
第 6 步：补文档、示例数据、打包演示          → README / examples / 演示视频
```

**关键经验：先写自检、再写界面。** 算法正确性由测试保证，界面只是“搬运工”，这样出问题能快速定位是算法还是界面。

## 六、如何修改与扩展（实操示例）

### 6.1 新增一个光学公式（约 15 分钟）

例：增加“球面折射近轴公式 `n1/u + n2/v = (n2−n1)/R`”。

```python
# core/formulas.py 末尾追加求解函数
def solve_spherical_refraction(n1=None, u=None, n2=None, v=None, R=None):
    """n1/u + n2/v = (n2-n1)/R，u、v、R 单位 cm。"""
    # 先做正数校验，再按“哪个为 None 就解哪个”写 if 分支
    if v is None:
        v = n2 * R * u / ((n2 - n1) * u - n1 * R)
    elif u is None:
        u = n1 * R * v / ((n2 - n1) * v - n2 * R)
    elif R is None:
        R = (n2 - n1) * u * v / (n1 * v + n2 * u)
    # ...（其余分支略）
    return {"n1": n1, "u": u, "n2": n2, "v": v, "R": R}, []

# 在 FORMULAS 列表末尾加一条记录
{
    "key": "spherical_refraction",
    "name": "球面折射近轴公式",
    "formula": "n1/u + n2/v = (n2-n1)/R",
    "symbols": [("n1","物方折射率 n1",""), ("u","物距 u","cm"),
                ("n2","像方折射率 n2",""), ("v","像距 v","cm"), ("R","曲率半径 R","cm")],
    "solve": solve_spherical_refraction,
},
```

界面会自动多出这个公式（因为界面是遍历 `FORMULAS` 的），无需改 app.py。

### 6.2 新增一种拟合类型

在 `core/fitting.py` 中实现函数，再在 `fit_data()` 里加一个 `if kind == "xxx":` 分支，最后在 app.py 的 `kind_rd` 里加一个选项即可。

### 6.3 修改实验报告模板

直接编辑 `core/report.py` 中 `build_report()`：改章节顺序、加“评分表”、换表格列名都在这一个函数里。字号/字体在 `_add_para` / `_set_run_font` 里调整。

### 6.4 修改界面布局

在 app.py 对应 `build_*_tab()` 里调整 `gr.Row()` / `gr.Column()` 嵌套即可；想加新功能页，照抄一个 `with gr.Tab("xxx"): build_xxx_tab()`。

### 6.5 进阶方向（可选扩展）

- 把数据存入 SQLite，实现实验记录历史管理；
- 加“导出实验数据表格 Excel”功能；
- 加常见实验模板（杨氏双缝、光电效应、牛顿环…）一键填充；
- 用 pyinstaller 打包成 exe，免安装分发。

## 七、常见报错与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: gradio` | 没用虚拟环境 / 没装依赖 | `pip install -r requirements.txt` |
| 端口被占用 `Address already in use` | 7860 被别的程序占用 | 改 app.py 的 `server_port` |
| 自检里自定义拟合 R² 为负 / 参数不变 | LM 不收敛或表达式/初值问题 | 检查表达式语法；给合理初值；先看数据是否本身非线性 |
| 图表中文方块 | 系统缺中文字体 | 在 fitting.py 的 `font.sans-serif` 列表补充本机字体名（如 `SimHei`） |
| 打开 CSV 乱码 | 编码问题 | 本工具用 UTF-8 读取，先用记事本另存为 UTF-8 |
| Gradio 版本 API 变动 | 依赖升级导致 | 本项目按 Gradio 6 编写；锁定版本可改 requirements.txt |

**通用排查思路**：先跑 `python self_test.py` 定位是算法还是界面；算法问题看 core/，界面问题看 app.py 的回调绑定。

## 八、面试讲解 & 招新提交包装

### 8.1 30 秒项目介绍（口头版）

> “我做的是一个光电实验数据处理助手。起因是我自己做大学物理实验时，发现每次都要手算公式、手动拟合、手动评不确定度，很繁琐。所以我把这四件事做成了一个本地网页工具：内置 14 个光学公式、三种数据拟合、教材标准的不确定度评定，还能一键生成 Word 实验报告。技术上我把算法层和界面层解耦，自定义拟合用的是我自己实现的 Levenberg-Marquardt 算法。用三个示例实验数据都验证过，拟合结果和理论值误差在 1% 以内。”

### 8.2 面试可能追问 & 回答要点

- **“最小二乘原理？”** → 残差平方和最小，求导为零得闭式解，公式见 3.2；
- **“R² 是什么？”** → 决定系数，1 − SS_res/SS_tot，越接近 1 拟合越好；
- **“A 类和 B 类不确定度区别？”** → A 类用统计方法（多次测量），B 类用非统计方法（仪器允差），合成取方和根；
- **“为什么用 t 因子？”** → 样本少时 t 分布比正态分布更保守，ν=n−1；
- **“LM 和梯度下降区别？”** → LM 结合高斯-牛顿与最速下降，用 λ 自适应切换，收敛快且稳；
- **“数据哪来的？”** → 示例数据是按真实物理参数 + 随机噪声模拟的（生成脚本在 examples/ 里，可复现）。
